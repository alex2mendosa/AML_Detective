# AML Screening Pipeline — Moldindconbank

Automated sanctions screening and risk assessment pipeline. Takes a company's
registration number and jurisdiction, screens it against OpenSanctions, enriches
it with director/owner information and industry classification, and produces an
AML compliance verdict.

## Architecture

```
(registration_number, jurisdiction)
           │
           ▼
  ┌─────────────────────┐
  │   screen_company    │
  ├─────────────────────┤
  │ 1. /match/default   │──► OpenSanctions match by reg number
  │ 2. /entities/{id}   │──► Full entity record with relationships
  │ 3. extract people   │──► Directors + owners (sanctioned flagged)
  │ 4. detect occupation│──► GPT-4.1-mini on name variants
  └─────────────────────┘
           │
           ▼
  ┌─────────────────────┐
  │  assess_aml_risk    │
  ├─────────────────────┤
  │ Fast path: is_target│──► GREEN + skip LLM
  │ else: GPT-4o +      │──► RED / YELLOW / GREEN
  │   structured output │    + reason + conclusion
  └─────────────────────┘
           │
           ▼
   Enriched result dict
```

## Output Schema

The final dict combines all layers. Fields are listed in output order.

### AML Verdict (generated by `assess_aml_risk`)

| Field | Type | Description |
|---|---|---|
| `risk_level` | `Literal["RED", "YELLOW", "GREEN"]` | Compliance risk classification. RED = engagement prohibited, YELLOW = enhanced due diligence required, GREEN = standard due diligence sufficient. |
| `safe_to_engage` | `bool` | Whether Moldindconbank may engage financially. `False` for RED and YELLOW, `True` for GREEN. |
| `reason` | `str` | 2–3 sentence justification for the risk level, citing specific risk topics and sanctions programs. |
| `aml_conclusion` | `str` | 3–5 sentence compliance conclusion in professional AML language, suitable for internal records. |
| `analysis_timestamp` | `str` (ISO 8601, UTC) | When the assessment was performed. |

### Entity Identification (from `extract_for_llm`)

| Field | Type | Description |
|---|---|---|
| `entity_id` | `str` | OpenSanctions internal ID (e.g. `NK-iid59npbdGKq3rEPaTtrai`). |
| `registration_number` | `str \| None` | First value from `properties.registrationNumber`. |
| `entity_name` | `str` | Primary caption of the matched entity. |
| `match_score` | `float` | OpenSanctions `logic-v2` match confidence (range 0–1). |
| `is_target` | `bool` | Whether entity is a sanctions target (vs. incidental mention). |
| `jurisdiction` | `str \| None` | ISO country code from `properties.jurisdiction`. |

### Risk Signals (from `extract_for_llm`)

| Field | Type | Description |
|---|---|---|
| `risks` | `dict[str, str]` | Topics present on the entity, mapped to human-readable descriptions from local `RISK_TOPICS` dict. |
| `other_topics` | `list[str]` | Topics not in `RISK_TOPICS` (e.g. `"poi"` = person of interest). |
| `sanctions_programs` | `dict[str, str]` | Program IDs → titles, mapped from local `sanc_prog_dict.json`. |
| `datasets` | `list[str]` | OpenSanctions dataset names the entity appears in (e.g. `us_ofac_sdn`, `ext_md_companies`). |
| `notes` | `list[str]` | Free-text notes from `properties.notes` (often name aliases). |
| `last_seen` | `str` (ISO 8601) | Last time OpenSanctions observed this record. |
| `total_matches` | `int` | Total results returned by `/match` for this query. |

### People (from `extract_people_from_entity`)

| Field | Type | Description |
|---|---|---|
| `sanctioned_persons` | `list[dict]` | Directors and owners flagged as sanctions targets. Each item: `{name, role, source}` where `source ∈ {"director", "owner"}`. |

### Occupation Enrichment (from `detect_occupation`)

| Field | Type | Description |
|---|---|---|
| `occupation.industry` | `str \| None` | Primary industry sector inferred from entity name variants. |
| `occupation.occupation` | `str \| None` | Specific business activity. |
| `occupation.confidence` | `float \| None` | LLM self-reported confidence (range 0–1). |
| `occupation.is_inferred` | `bool \| None` | `False` if occupation is explicitly stated in names, `True` if guessed from brand name alone. |

## Risk Classification Rules

The `assess_aml_risk` agent uses these rules:

- **RED** — Direct, prohibitive risk. Examples: direct government sanctions,
  terrorism, war crimes, asset freezes, trafficking, export controls on the
  entity itself.
- **YELLOW** — Requires enhanced due diligence before engagement. Examples:
  linked to a sanctioned entity (but not directly sanctioned), debarment only,
  regulatory warnings, shell/offshore flags, counter-sanctions, moderate match
  scores.
- **GREEN** — No significant risk indicators. Standard DD is sufficient.

The agent is instructed not to invent risks that are not present in the input
data and to cite specific topics, programs, and datasets in the justification.

## Fast Path

If `is_target` is `False` on the matched entity, `assess_aml_risk` skips the LLM
call entirely and returns GREEN with a canned reason. This avoids unnecessary
OpenAI spend on the common case where a registration number matches a company
that is not actually on any sanctions list.

## Usage

```python
raw = screen_company("1021600048015", "md")
if raw:
    final = assess_aml_risk(raw)
    print(json.dumps(final, indent=2, ensure_ascii=False))
else:
    print("No match found in OpenSanctions.")
```

## Known Limitations

- **No graph traversal.** The OpenSanctions API does not expose parent/child
  company relationships, so the pipeline cannot trace ultimate beneficial
  ownership beyond directors and direct owners returned in the entity record.
- **Jurisdiction is a soft filter.** OpenSanctions' `logic-v2` matcher treats
  `jurisdiction` as a weak signal. A Russian OGRN passed with `jurisdiction="md"`
  may still match if the entity has a Moldovan presence. Post-hoc verification
  is recommended for strict jurisdiction enforcement.
- **Director-level risk not always surfaced.** The agent receives
  `sanctioned_persons` but the prompt does not currently force the conclusion
  text to name them when company-level risks are already sufficient. Consider
  strengthening the prompt if director-level flagging is required in records.
- **Occupation detection relies on name variants only.** Companies with generic
  brand names (e.g. "AIRROCK SOLUTIONS") will return `industry: "Unknown"` with
  low confidence, as there is no industry signal in the name alone.

## Configuration

| Variable | Purpose |
|---|---|
| `OPENSANC_API_KEY` | OpenSanctions API key, passed as `Authorization: ApiKey <key>`. |
| `OPENAI_API_KEY` | Used by both the occupation detector (`gpt-4.1-mini`) and the AML assessment agent (`gpt-4o`). |

## External Data Files

| File | Purpose |
|---|---|
| `sanc_prog_dict.json` | Maps OpenSanctions program IDs (e.g. `US-RUSHAR`) to human-readable program titles. Loaded once at module level. |

## Match Parameters

Defined in `PARAMS` at module level:

- `algorithm`: `"logic-v2"` — OpenSanctions' current recommended matcher.
- `limit`: `3` — maximum results per query.
- `threshold`: `0.7` — minimum match score to return.
- `changed_since`: `"2015-01-01"` — only entities updated after this date.
